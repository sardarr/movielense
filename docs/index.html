What these mean
  • Split strategy — per user, the single most-recent positive is test, second-most-recent is val, everything else is train (this run — published NCF / SASRec protocol).
  • Candidate strategy — full_catalog: rank every unseen item; metrics are pessimistic and reward popularity-aware models. sampled: rank the held-out positive against N random negatives; metrics are permissive and reward expressive models.
  • Rating threshold — only ratings ≥ this count as positive interactions for ranking metrics; lower-rated rows still go into training as implicit signal.

Models — architecture & training recipe

For each model in the comparison: family, what it consumes at fit time, the training procedure, scoring cost, where it shines, and how readable its decisions are.

ModelTypeInputsTrainingInferenceUse caseInterpretability
random Baseline (random) none no training — generates a deterministic random score per (user, item) using a hash of seed and user id O(1) per pair sanity-check floor: any real model must beat this n/a
popularity Baseline (popularity) global item interaction counts on the training split single pass over training data to count interactions per item O(1) lookup per (user, item) strong baseline; hard to beat for users with mainstream taste; provides no personalization trivial — score IS popularity
itemknn Memory-based collaborative filtering (item-item kNN) binary user-item interaction matrix compute cosine similarity between every pair of items; keep the top-k neighbors per item score(u, i) = sum of sim(i, j) for j in user u's history (sparse vector dot product) transparent neighbor explanations ('because you watched X'); strong on dense items; struggles with cold-start items high — top contributing neighbors per recommendation
als Matrix factorization (Alternating Least Squares, implicit feedback) user-item interactions weighted with confidence c(u,i) = 1 + alpha * indicator(u liked i) alternate ridge regression: fix item factors, solve for user factors (and vice versa) for K iterations score(u, i) = U[u] @ V[i] (single dot product of factor vectors) fast batch scoring at scale; learned latent factors capture taste similarities; standard production baseline low — latent factors have no semantic labels
bpr Neural pairwise learning-to-rank (Bayesian Personalized Ranking, PyTorch) implicit feedback as (user, positive_item, sampled_negative_item) triples minimize -log sigmoid( - ) over many epochs with Adam; negatives are uniformly sampled items the user hasn't interacted with score(u, i) = U[u] @ V[i] (dot product of learned embeddings) directly optimizes pairwise ordering, which aligns with ranking metrics like NDCG; matches the goal of top-K recommendation better than rating-prediction MF low — learned embeddings; can be probed via nearest-neighbor inspection
lgbm Learning-to-rank with gradient-boosted trees (LightGBM LambdaRank) engineered features per (user, item): user side-info (age, gender, occupation), user behavior (interaction count, mean rating, genre preference), item content (genres, release year, popularity, mean rating), and an interaction term (user-item genre affinity) for each user, sample N negatives per positive; train LambdaRank with NDCG metric; trees split features to maximize ranking quality predict relevance for each candidate item via summed leaf contributions across trees supports cold-start (no need for prior interactions if features exist) and is fully interpretable via gain / SHAP; slower at scoring than dot-product models — best when you control candidate-set size upstream high — feature importance (gain, split, SHAP) directly available
sasrec Sequential transformer (Self-Attentive Sequential Recommendation, PyTorch) per-user time-ordered item sequence (truncated to max_len most-recent positives); uses interaction timestamps as the ordering signal stack of N causal-masked self-attention blocks with learned positional embeddings; per-position BPR loss: maximize sigmoid( - ); Adam over batched user sequences encode each user's training history once, cache the final hidden state h_u; score(u, i) = — same dot-product cost as ALS / BPR after caching captures sequential patterns and recency that bag-of-interactions models (ALS, BPR) ignore; strong when item discovery follows trends or session structure low — attention weights can be probed but require additional tooling
sasrec_content Content-collaborative sequential transformer (SASRec + frozen MiniLM) same time-ordered sequences as SASRec, plus a frozen sentence-transformer (all-MiniLM-L6-v2) embedding of '{title}. Genres: ... . Year: ...' for each item item representation = learned id-embedding + linear projection of frozen text embedding; transformer + BPR loss are unchanged. Only the projection head and id-embedding move during training; the 384-d text vectors are read-only score(u, i) = ; same dot-product cost as plain SASRec after the fused item matrix is cached tests whether semantic content (title + genres) can lift cold or long-tail items where pure id-embeddings have little signal; expected to help most for items with few training interactions low — semantic neighborhoods inspectable via text-embedding cosine, but model decisions still latent
sasrec_content_only Content-only sequential transformer (SASRec without id-embeddings) same time-ordered sequences as SASRec, but the item representation is built exclusively from frozen sentence-transformer embeddings — there are no learned per-item id vectors at all item representation = linear projection of frozen text embedding (no id-embedding term); transformer + BPR loss are unchanged. Only the projection head and transformer trunk train score(u, i) = ; works for items the model has never seen during training, since their representation comes purely from text cold-start probe: how much of SASRec's signal comes from collaborative id-embeddings vs the semantic content alone? A floor for content-driven recommendation low — item representations are projected text; user state still latent
